# 科研技能目录维护

本流程维护 [catalog.json](../../catalog.json) 中的来源、模块记录及对应本地文件，重点是编写准确的 purpose、use_when，供 hub 筛选、比较并推荐模块。

catalog.json 用于选择模块和定位本地入口；具体参数、脚本用法及输出约定在执行时读取原始 skill 和必要引用。

## 导入、更新与修正

复制时记录新增文件，覆盖已有文件前保留临时备份。涉及本次范围外的模块或共用文件时，先说明影响并确认。

### 导入模块

1. 确定范围：多 skill 包未指定范围时，列出各 skill 及用途，确认全部导入还是指定导入；已有明确选择则沿用。
2. 读取原文并检查可行性：读取来源仓库中的 SKILL.md 及必要引用，核实能力、产物和依赖。
   - 检查技能及其依赖文件（含目录外和共用依赖），缺失时先从来源补齐；无法补齐则向用户报告缺项、影响和建议，暂不登记。
   - 执行条件未满足或原始技能需修改才能使用时，说明问题、影响和处理方案，等待用户明确要求继续后再导入。
3. 保存模块：按原包布局，将所选技能、依赖文件和许可复制到 `modules/<来源id>/`，关闭各技能的自动调用。
4. 编写记录：按下文填写 catalog.json 中的 sources 和 modules 记录；未选中的 skill 不自动登记。

### 更新模块

按 path 定位模块，比较新旧文件，沿用导入时的可行性检查和调用策略，更新模块及 catalog.json 中的对应记录。入口迁移时同步修改原记录的 path，避免重复登记。

### 修正模块记录

核对原始 `SKILL.md`，修正 `catalog.json` 中填写错误或与原文不符的字段。仅修改 catalog.json 时，无需重新复制或更新模块文件。

## catalog.json 的结构与字段

catalog.json 顶层包含 sources 和 modules。模块默认从仓库导入。

### sources：来源仓库

每个仓库一条记录，只包含以下字段：

- `id`：唯一的来源目录名，对应 `modules/<来源id>/`。
- `repo`：仓库地址或 `owner/repo` 标识。

### modules：已导入技能

每个已导入模块一条记录，只包含以下字段：

- `name`：取自原始 `SKILL.md`。
- `path`：
  - 相对于 hub 根目录，格式为 `modules/<来源id>/<仓库内相对路径>`，以 `/` 分隔；来源 id 对应 sources.id。
  - 必须指向 hub 内实际存在的 `SKILL.md`。每个入口只登记一次，同名模块按 path 区分。
- `purpose`：
  - 根据原文，用一句简短的话说明模块处理什么对象、完成什么任务、形成什么结果。
  - 保留有助于选择的能力特征，例如双语对照、方法讲解或多轮评审。
- `use_when`：
  - 从用户需求出发，说明适用的问题、期望结果，以及必要的学科、输入材料或输出形式。
  - 按原文说明关键前提，如完整论文、真实实验结果或特定评审服务；不把默认偏好、可选服务或特定示例写成必需条件或唯一适用范围。
  - 比较近义模块的目标、产物、方法或必要依赖，说明各自适合的需求；多个模块都适用时保留可比较的差异，不强行划成互斥选项。

purpose 回答“模块能做什么”，use_when 回答“当前任务在什么条件下适合使用它”。功能相同的模块可以使用相同 purpose，通过 use_when 写清适用条件的差异；不能只将 purpose 改成“需要……时”作为 use_when。两项均须依据原文，具体执行步骤、常规安装和路径配置留在原始 skill 中。

## 校验与清理

1. 运行[只读校验工具](scripts/validate_catalog.py)，检查已保存的 catalog.json 和本地入口；必要时用 `--require-local PATH` 确认指定入口已登记。
2. 校验失败时修正并重检；无法完成则恢复旧文件和 catalog.json，清理本次新增且未被其他模块使用的文件，并说明问题。
3. 校验成功后删除本次临时文件、旧版备份及不再使用的旧文件，保留模块必需文件、许可和用户文件；汇报变更、校验结果和尚缺的运行条件。
